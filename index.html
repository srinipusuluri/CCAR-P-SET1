Exam blueprint (weight by domain)

The single most useful exam instinct: this is a trade-off exam, not a right-answer exam. Almost every item is really asking "match the pattern/model/protocol to the actual constraint" — the wrong answers are usually the ones that ignore a stated constraint (cost, latency, least privilege, an SLA) in favor of a default.

Core concepts & vocabulary

The architecture-level vocabulary this exam assumes — patterns, trade-offs, and the regulatory terms named explicitly in the guide.

Architectural patterns

PatternWhat it isReach for it when…
Workflow-basedFixed, predefined processing steps.The sequence is known, branching is predictable, success is easy to verify.
AgenticClaude dynamically plans and decides its own next action.The right next step depends on intermediate results and can't be enumerated up front.
Augmented LLMA single retrieval/tool-augmented generation call, no multi-step orchestration.The task is a simple, single-step grounded answer.
Multi-agentMultiple specialized agents coordinated by an orchestrator.A complex problem decomposes into components needing different expertise or tools.

Integration mechanisms

MechanismBest fit
MCPStandardized tools/resources usable by multiple clients without bespoke integration per client.
Direct API / CLIA simple, tightly-scoped, single-purpose integration where standardized multi-client discovery isn't needed.
Agent-to-agentInternal coordination between agents — needs an explicit authorization boundary, not unrestricted access.
Decision rule — least privilege: the correct fix for excess agent capability is removing what a role doesn't need — eliminating the attack surface — not just logging it or adding a confirmation prompt (those are detective/compensating controls, not privilege reduction).

Regulatory & governance terms you must recognize

GDPR — EU data protection: data minimization and data-subject rights (access, correction, deletion).
HIPAA — U.S. healthcare: safeguards for protected health information (PHI), minimum-necessary access.
FedRAMP — authorization requirements for cloud services used by U.S. federal agencies.
Human-in-the-loop — required validation for high-impact or uncertain outputs; consequential decisions shouldn't be fully automated.
Bias & fairness — systematically unequal outputs across groups with no legitimate basis.
Transparency — disclosing AI involvement where it materially affects the user's understanding.
Prompt caching — reusing a static prompt prefix across calls to cut latency and cost.
Progressive discovery — fetching context incrementally as needed, instead of loading a monolithic context upfront.

Glossary

MQC — minimally qualified candidate; the exam's performance target, set by a formal standard-setting study.
Criterion-referenced — scored against a fixed standard, not curved against other candidates.
Capability bloat — an agent/tool configuration granting more capability than a role actually needs.
Least privilege — scoping access to only what's required, removing (not just monitoring) unnecessary capability.
RAG — retrieval-augmented generation: grounding responses in retrieved, indexed content.
Chunking — splitting documents for indexing, ideally aligned to semantic/section structure.
A/B testing — comparative evaluation of two configurations against the same criteria.
Model mismatch — a failure category distinct from hallucination or prompt failure: the wrong model tier for the task.
Stratified evaluation — checking accuracy by segment, since an aggregate metric can mask a subgroup's poor performance.
SLA — a service-level agreement (e.g., uptime, latency) the architecture must be designed to meet.
Lifecycle phases — discovery, design, implementation handoff, monitoring, and iteration.
Zero-shot / few-shot / chain-of-thought — prompting techniques for, respectively, no examples, demonstrated examples, and step-by-step reasoning.
Five reflexes that pass this exam:
  1. Match the architectural pattern, model tier, and integration mechanism to the stated constraint — never default to the biggest, most autonomous, or most standardized option.
  2. Apply least privilege by removing unneeded capability, not just monitoring or confirming it.
  3. Diagnose failures by category first (hallucination vs. prompt failure vs. model mismatch vs. retrieval/indexing) before proposing a fix.
  4. Treat human-in-the-loop review and honest stakeholder communication as required, not optional, for consequential or uncertain outputs.
  5. Name the specific regulation (GDPR, HIPAA, FedRAMP) that actually applies to the data and deployment context — don't treat compliance as one interchangeable checkbox.
